# Plan de Evaluación de Riesgos o Risk Management Plan
**Proyecto:** Sistema de Gestión Comercial "Frankie"

|    ID    | Descripción del Riesgo                                                                                                               |  Impacto  | Probabilidad | Estrategia de Mitigación / Plan de Contingencia                                                                                                        |
| :------: | :----------------------------------------------------------------------------------------------------------------------------------- | :-------: | :----------: | :----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R-01** | **Conflictos de Merge en Git por desarrollo paralelo:** Cambios simultáneos en archivos compartidos destruyen código de otro módulo. | **Alto**  |   **Alta**   | **Mitigación:** Modularización estricta por paquetes (`vistas`, `dominio`, `infraestructura`). Prohibido tocar código de otro módulo sin aviso previo. |
| **R-02** | **Fallo en Triggers de SQLite:** Que la base de datos no descuente el stock o permita ventas sin stock suficiente.                   | **Alto**  |  **Media**   | **Contingencia:** Desarrollo de la suite `tests/test_stock.py` en la Semana 5 para validar el comportamiento de los triggers antes de integrar la UI.  |
| **R-03** | **Retraso en el Camino Crítico:** Demora en la entrega del Módulo 1 (Core) bloqueando la integración del Panel Principal.            | **Alto**  |   **Baja**   | **Mitigación:** Creación de un mock/boceto temporal del Panel Principal para no frenar el diseño visual de los módulos 2, 3 y 4.                       |
| **R-04** | **Bloqueo del archivo SQLite (`database is locked`):** Conexiones concurrentes mal cerradas colapsan la interfaz.                    | **Medio** |  **Media**   | **Mitigación:** Implementación estricta del Patrón Singleton en `conexion.py` utilizando administradores de contexto (`with conexion:`).               |
| **R-05** | **Desviación del Alcance (Scope Creep):** Intentar agregar demasiadas funcionalidades no requeridas dentro de las 6 semanas.         | **Medio** |   **Alta**   | **Mitigación:** Respetar estrictamente la EDT/WBS aprobada en la Semana 1. Toda mejora adicional queda para un "Fase 2".                               |
